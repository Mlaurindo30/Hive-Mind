# Sinapse — Knowledge Graph Query

## Overview

This skill queries the knowledge graph generated by Graphify from the
Obsidian vault (`cerebro/`). Use it when you need:

- Relationships between concepts ("How does X connect to Y?")
- To locate decisions ("Where is the decision about pricing?")
- To understand the structure of the knowledge base ("Which projects use Go?")
- To discover non-obvious connections across areas of the vault
- Graph-level metrics (core abstractions, community membership, overall stats)
- GitHub PR impact against the graph (which communities/files a PR touches, review priority)

For everything outside graph topology — general project state/history,
decisions, patterns, code, or vault content — prefer `sinapse_query` (see
`config/sinapse-agent-prompt.md`), which fuses Graphify together with six
other backends. This skill is the narrow, Graphify-specific entry point.

## How to use

In Hermes, Claude Code, Codex, or OpenCode:

```
/sinapse-query "decision about VPS migration"
/sinapse-query "auth flow database"
/sinapse-query "which projects use TypeScript"
```

## Equivalent command (terminal)

```bash
cd ~/Documentos/Projects/sinapse_agent
python3 -c "
import json, sys
graph = json.load(open('cerebro/cortex/occipital/grafo/graph.json'))
query = sys.argv[1].lower()

# Search nodes
for node in graph.get('nodes', []):
    if query in node.get('name', '').lower():
        print(f\"Node: {node['name']} (type: {node.get('type', 'unknown')})\")

# Search edges
print()
print('Connections found:')
for edge in graph.get('edges', []):
    if query in str(edge.get('source', '')).lower() or query in str(edge.get('target', '')).lower():
        print(f\"  {edge['source']} → {edge['target']} ({edge.get('relationship', 'related')})\")
" "<query>"
```

## Available MCP tools

If the Graphify MCP server is running (`config/mcp/graphify.json`, launched via
`scripts/services/mcp-server.sh`), these tools are available:

| Tool | Description |
|------|-----------|
| `query_graph(question, mode?, depth?, token_budget?, context_filter?)` | BFS/DFS search over the knowledge graph; returns relevant nodes/edges as text context |
| `get_node(label)` | Full details for a specific node by label or ID |
| `get_neighbors(label, relation_filter?)` | All direct neighbors of a node, with edge details |
| `get_community(community_id)` | All nodes belonging to a given community (0-indexed by size) |
| `god_nodes(top_n?)` | The most-connected nodes — the core abstractions of the graph |
| `graph_stats()` | Summary statistics: node count, edge count, communities, confidence breakdown |
| `shortest_path(source, target, max_hops?)` | Shortest path between two concepts in the graph |
| `list_prs(base?, repo?)` | Open GitHub PRs with CI status, review state, and graph impact (which communities each PR touches) |
| `get_pr_impact(pr_number, repo?)` | Detailed graph impact for a specific PR — files changed, communities affected, nodes touched |
| `triage_prs(base?, repo?)` | All actionable open PRs (correct base, not stale) with full graph-impact data, for review-priority/merge-order reasoning |

## Notes

- `graph.json` regenerates automatically (watch mode) when vault files
  change.
- The first run can be slow (graph build). Subsequent queries are
  instant.
- If the graph is stale, run `./scripts/graph/build-graph.sh --force`.
